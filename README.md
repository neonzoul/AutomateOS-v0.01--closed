# AutomateOS v0.01

> **This is what happened when AI made my ambition larger than my engineering experience.**

**Archived — no longer maintained and not recommended for production use.**

AutomateOS v0.01 was one of my first serious attempts to build a complete software product with AI.

The idea was a self-hosted workflow automation platform: create workflows, connect triggers and actions, call external APIs, run jobs in the background, and inspect what happened afterward.

Think of it as an early experiment in the territory of tools like Zapier or n8n.

## What I was exploring

The project pushed me into parts of software development I had barely touched before:

- frontend and backend separation
- APIs and webhooks
- authentication
- PostgreSQL and Redis
- background workers and queues
- asynchronous execution
- workflow modeling
- Docker
- CI/CD and deployment

AI made it possible to attempt all of these at once.

That was both the strength and the weakness of the project.

I could build concepts faster than I could fully understand the cost and consequences of each architectural decision.

The result contains real working ideas alongside premature abstractions, over-engineering, optimistic documentation, and decisions I would make very differently today.

## Why it is public

I am keeping this repository because it captures an unusual moment in software development for me.

For the first time, implementation was no longer the main limitation.

AI made it possible for one person with limited engineering experience to attempt a surprisingly large system.

The interesting part, looking back, is not whether every technical decision was correct.

It is seeing what happens when the cost of turning an idea into code suddenly collapses.

I have intentionally not rewritten the project to match what I know today.

The mistakes are part of the artifact.
